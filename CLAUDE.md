## Next.js 16 — read the bundled docs before writing code

This project runs **Next.js 16.3.4**, which has breaking changes from older versions. AGENTS.md is auto-maintained by `next dev` and points at the authoritative, version-matched docs in `node_modules/next/dist/docs/` — read the relevant guide there before writing any code, and heed deprecation notices. `AGENTS.md` is regenerated by `next dev`; don't remove it from diffs — commit it with your work.

The changes most likely to trip up code written from memory:

- **Async Request APIs (breaking).** `cookies()`, `headers()`, `draftMode()`, `params`, and `searchParams` are async-only; synchronous access was fully removed in 16. Type-safe helpers are available: `PageProps<'/route'>`, `LayoutProps<'/route'>`, `RouteContext<'/route'>` (e.g. `export default async function Page(props: PageProps<'/blog/[slug]'>) { const { slug } = await props.params }`). `app/layout.tsx` already uses `LayoutProps<"/">`.
- **`middleware` → `proxy`.** The `middleware` filename and export are deprecated; use `proxy.ts` / `export function proxy()`. `proxy` runs on `nodejs` runtime (edge is unsupported).
- **`revalidateTag` now requires a second argument** (a `cacheLife` profile, e.g. `revalidateTag('posts', 'max')`). New `updateTag` (read-your-writes, Server Actions) and `refresh` APIs exist in `next/cache`.
- **Turbopack is the default** for `next dev` and `next build` — no flags needed. A custom `webpack` config will fail the build unless you pass `--webpack`.
- **`cacheComponents`** (top-level config) replaces the removed `experimental.dynamicIO` / `experimental.useCache` and PPR flags.
- **Parallel route slots require explicit `default.js`** files, or the build fails.
- **`next/image` defaults changed**: `images.qualities` defaults to `[75]`, `minimumCacheTTL` to 4h, and local images with query strings need `images.localPatterns.search` config.

These are highlights only — always confirm against `node_modules/next/dist/docs/`.

## Architecture

Standard Next.js App Router structure. Routes live in `app/` (`app/layout.tsx` is the root layout with Geist fonts via `next/font/google`). `.next/types/` drives typed routes (`PageProps`/`LayoutProps`); run `npx next typegen` if route types go stale. The `@/*` path alias maps to the repository root.

- **Styling: Tailwind CSS v4, CSS-first config.** No `tailwind.config.js` — theme is defined inline in `app/globals.css` with `@import "tailwindcss"` and the `@theme inline` directive, wired to the Geist CSS variables. Add design tokens there, not in a config file.
- **Tooling**: TypeScript strict mode; ESLint flat config (`eslint.config.mjs`) using `eslint-config-next` core-web-vitals + typescript presets; PostCSS via `@tailwindcss/postcss`.

## Workflow: Spec Driven Design

Per the README, the project builds features **spec-first** using the `/spec` and `/spec-impl` skills from [Klerith/fernando-skills](https://github.com/Klerith/fernando-skills) (install with `npx skills@latest add Klerith/fernando-skills`). The `spec/` and `spec-impl/` directories don't exist yet — when implementing features, follow this workflow: write a spec first, then implement against it.
